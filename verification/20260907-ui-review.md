# onlyyuuka 3案のUI・動作確認

確認日: 2026-09-07
環境: ローカル静的サイト + Codex In-app Browser / Computer Use
対象: gallery・atelier・journal 各4ページ、比較ページ、準備リスト。

## 制作順序
A案の4ページ・準備リスト・提出ZIP・プレビューPDFを完成させてから、B/C案を制作。Aチェックポイント時は自動ブラウザの21確認項目を合格。

## Computer Useで確認した範囲
- 各4ページを320 / 390 / 768 / 1024 / 1440pxで表示。横方向のはみ出し、見出し構造、読込済み画像の欠損を確認。
- 比較と準備ページは320 / 390 / 1440pxで確認。表はモバイルで表の領域だけを横スクロール。
- PC・スマホの画面を目視し、見出しの改行、文字と写真の重なり、余白、作品画像の全体表示を確認。
- 各案で作品カテゴリを操作し、バッグ1件に絞れることを確認。
- 各案で作品詳細を開き、写真・素材・仕様の注記・相談導線を確認。
- 作品詳細からContactへ遷移し、作品名と相談種別が引き継がれることを確認。
- テスト用の名前・メールを入力し、確認画面に表示、未送信の案内、修正時の入力保持を確認。
- 各案のニュースレターで登録されないサンプル確認を表示。
- スマホメニューとFAQの開閉、Escapeでの閉じる動作を確認。
- 全14 HTMLの相対リンク・画像・アンカーを静的検証。JavaScript構文検査を合格。
- ブラウザのerrorログなし。

## 発見して修正した点
1. AのスマホHeroでグリッドの最小幅が画面を押し広げた。minmax(0,1fr)と文字サイズを調整。
2. スマホの作品セクション見出しが横並びリンクに押されて不自然に折れた。縦に並べる構成に変更。
3. Cの390px記事カードが最小コンテンツ幅で横にはみ出した。列幅の最小値と子要素min-widthを修正。
4. Bの390px見出し「また使いたくなる」の末尾だけが改行した。ビューポートに連動する文字サイズを調整。
5. CのHero見出しはスマホで「帯だった。／今は、／テーブルの上。」の3行に整理。
6. 印刷ではスマホCSSが適用され、比較案が分割された。印刷専用の3列と固定プレビュー高さを追加。

## スコープ
確認したのはブラウザ上のUIサンプル。問い合わせの実送受信、メール配信、本人情報や実作品仕様の最終承認は本番制作時に実施する。

## 提案書のドキュメント化
ユーザーの追加指定により、編集用Wordと同内容PDFを7ページで作成。3案の狙い、掲載内容の粒度、写真・原稿の数量と用途、確認分担、公開までの準備を収録。Wordを描画し、7ページの日本語・画像・表・改ページを目視確認。比較ページと準備ページから取得できる。
